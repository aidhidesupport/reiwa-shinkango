## 条件分岐つき実行計画

### A. まず公開するか、MVP改善を続けるか

条件: 1週間以内に外部公開したい。

- Yes: P0だけに絞る。法務文書、PostgreSQLステージング、環境変数、バックアップ、ヘルスチェックを優先する。
- No: P1を先に進める。修正提案、エラー表示、編集者ダッシュボード拡張、管理者画面を実装してから公開準備へ戻る。

止める条件:

- 利用規約とプライバシーポリシーが雛形のままなら公開しない。
- 本番DBでログイン、投稿、評価、通報、推奨訳設定が未確認なら公開しない。

### B. 本番DBを先に決めるか

条件: Supabase、Neon、Render PostgreSQL など、実際に使うPostgreSQLが決まっている。

- Yes: `DATABASE_URL` と `DIRECT_URL` を設定し、`npm run prisma:migrate:postgres`、`npm run seed`、`npm run build:postgres` をステージングで実行する。
- No: DB候補を1つに絞る。無料枠や接続方式の比較に時間を使いすぎず、まずステージングDBを1つ作る。

分岐:

- migration が失敗する: 生成された `prisma/schema.postgres.prisma` と migration SQL を確認し、SQLiteとの差分を修正する。
- seed が失敗する: 初期管理者、重複slug、必須環境変数を確認する。
- build は通るが実操作が失敗する: serverless接続、pooler設定、`DIRECT_URL` の向き先を確認する。

完了条件:

- ステージングで `/api/health` が成功する。
- 初期管理者でログインできる。
- 投稿、評価、コメント、通報、推奨訳設定、非表示処理を一巡できる。
- `npm run backup:postgres` の出力を復元できる。
