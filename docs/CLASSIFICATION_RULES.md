# 分野・タグの分類ルール

最終更新: 2026-07-26

## 目的

使われ方を検索・比較しやすくし、投稿者と編集者が同じ基準で分類できるようにする。
言葉そのものの由来ではなく、登録する意味、合う場面、例文を基準に判断する。

## 基本原則

1. 分野は、使われ方ごとに主な利用場面を1つ選ぶ。
2. タグは、検索結果を絞るのに役立つ論点を原則1〜3個付ける。
3. 複数の分野で意味や適切な日本語案が変わる場合は、別の使われ方に分ける。
4. 分野を判断できない投稿は「未分類」で受け付ける。推奨する日本語案を決める前に編集者が確認する。
5. 分類数を埋めることを目的に、実例のない投稿や使われ方を作らない。

## 分野

| 分野 | 対象 | 境界の目安 |
|---|---|---|
| ビジネス | 経営、営業、事業運営、取引、一般的な社内業務 | 採用・育成が中心なら「人事」、システム実装が中心なら「IT」 |
| 行政 | 国・自治体の制度、公共サービス、法令、行政文書 | 企業内の一般的な法令対応や統治は「ビジネス」 |
| IT | ソフトウェア、情報基盤、データ、画面設計、技術運用 | 広告効果や顧客行動の分析が中心なら「マーケティング」 |
| マーケティング | 市場調査、顧客獲得、広告、販売促進、ブランドづくり | SNS固有の投稿・拡散・反応なら「SNS」 |
| 人事 | 採用、育成、評価、労務、キャリア、組織開発 | 部門を問わない経営・組織運営なら「ビジネス」 |
| SNS | 投稿、アカウント、拡散、交流、SNS上の反応 | SNSを含む広い広告・顧客獲得施策なら「マーケティング」 |
| 教育 | 学校、授業、学習、教材、指導、教育制度 | 社員研修や職業能力の開発が中心なら「人事」 |
| 日常 | 仕事や制度の専門場面に限らない、暮らしや一般会話 | より具体的な専門分野がある場合はその分野 |

### 複数分野にまたがる場合

- 例文が最も自然に現れる分野を選ぶ。
- 同じ意味のまま複数分野で使える場合は、最も中心的な分野を1つ選び、必要ならタグで補う。
- 分野によって意味、日本語案、合う場面が変わる場合は、使われ方を分ける。
- 「教育」「日常」は初期データでは0件だが、既存6分野では表しにくい独立した利用場面なので残す。

## タグ

| タグ | 付与する対象 |
|---|---|
| 会議 | 会議の準備・進行・合意・決定・次の行動 |
| 企画 | 構想、計画、戦略、製品・サービス設計 |
| 分析 | 指標、調査、測定、比較、結果の読み取り |
| 組織 | 統治、意思決定、部門連携、組織運営 |
| 開発 | ソフトウェア・製品の開発、基盤、技術運用 |
| 広報 | 対外発信、広告、メディア、SNS、販売促進 |
| 人材 | 採用、育成、評価、技能、キャリア |
| 社会 | 公共性、権利、多様性、包摂、地域や社会規範 |

投稿画面では新しいタグも入力できるが、既存タグを優先する。入力上限は不正利用防止のため
20個としているが、通常の投稿は1〜3個、多くても5個までを編集上の目安とする。

## タグの追加・統合・廃止

### 追加

次の条件をすべて満たすものを正式なタグとして採用する。

- 既存8タグのいずれでも目的を十分に表せない。
- 単一の言葉に固有ではなく、異なる使われ方3件以上で継続利用できる。
- 意味が短く説明でき、投稿者が同じ判断で付与できる。

### 統合

- 表記違い、略称、同義語は、より一般的で意味の明確な代表表記へ統合する。
- 統合前に、そのタグが付いた使われ方を確認し、意味が異なるものは別タグとして残す。
- 統合理由と対象件数を編集履歴または運用記録に残す。

### 廃止

- 意味が広すぎる、他タグと常に併用され単独の絞り込み価値がない、誤解が多いタグは新規付与を止める。
- 既存データは代表タグへ移行してから削除する。
- 分野はタグより影響範囲が大きいため、追加・統合・廃止の前に検索画面と既存件数を確認する。

## 編集レビューの確認項目

- 分野が言葉全体ではなく、その使われ方に対して選ばれているか。
- タグが日本語案の表現ではなく、利用場面や論点を表しているか。
- 同じ意味のタグが別表記で増えていないか。
- 1件だけに固有のタグや、検索に使いにくい長いタグになっていないか。
- 未分類のまま推奨状態を設定しようとしていないか。

公開画面の案内は `/rules/classification` に掲載する。この文書を運用上の正本とし、
分類を変更した場合は公開画面、投稿フォームの説明、初期データを同時に見直す。
